# /release-notes

Highlights for the people who consume the release — **not the commit log**. Internal refactors, build changes, and test work stay out.

Source the content from the `CHANGELOG.md` section for the version, and on the library track from the ABI report as well.

Structure: what's new · what changed and what a reader must do about it · what's fixed · **breaking changes with the concrete migration step**, first if any exist.

On the library track add migration guidance summarising deprecations, their sunset versions, and their replacements.

Print for the user to paste into the release. Do not commit it.
